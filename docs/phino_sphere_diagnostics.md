# PHINO sphere overtravel diagnostics

The seven-geometry pilot reported **zero valid Push X and Push Y trajectories for the sphere** because each exceeded the grid generator's 0.25 m raw-displacement cutoff. This is not, by itself, evidence of unstable simulation: a sphere can roll beyond that distance.

This diagnostic reuses the unchanged PHINO action schedules and MuJoCo scene loading, but **does not stop at 0.25 m**. It records when the cutoff was crossed and attempts to save the full 50-frame trajectory. It stops only if MuJoCo emits a numerical warning, the state becomes nonfinite, or motion passes the diagnostic emergency limit (3 m by default). It preserves any completed frames if stopped early.

## Run on Brown

From the existing SIMPACT environment and repository root:

~~~bash
git pull --ff-only origin phino-physics-experiments
python scripts/diagnose_phino_sphere.py --self-test

MUJOCO_GL=egl python scripts/diagnose_phino_sphere.py --render \
  | tee results/phino_sphere_diagnostics.log
~~~

The run evaluates **Push X and Push Y** for all 3 masses × 3 friction values (18 trials). It renders two nominal-setting GIFs (mass = 0.30 kg, friction = 0.30). To skip rendering and the Pillow dependency, omit \`--render\`.

The required scene is \`results/phino_mesh_scenes_v1/object_sphere/scene.xml\`, generated by \`scripts/build_phino_mesh_scenes.py\`.

## Output

Under \`results/phino_sphere_diagnostics_v1/\`:

- \`manifest.json\`: run settings, all 18 trial statuses, times of first cutoff crossing, maximum displacement, tilt, and velocities
- \`summary.csv\`: same trial-level comparison, suitable for quick inspection
- \`trajectories/*.npz\`: 50×13 diagnostic trajectories, or shorter partial trajectories if the emergency stop was reached
- \`renders/*.gif\`: nominal Push X and Push Y fixed-camera visualizations, when \`--render\` is set

The existing \`results/phino_mesh_grid_v1\` is not touched. This diagnostic **does not relabel or admit rejected training trajectories**.

The output directory must not already exist. For a repeated run, pass a new path using \`--output-dir\`.

## Decision before modifying the grid

Inspect the GIFs and trajectory metrics. If a sphere rolls smoothly and stays numerically stable, test a *separate*, explicitly documented validation rule for rolling objects. Do not silently raise the cutoff or exclude rejected cases. A new acceptance rule should be evaluated on fresh objects, not tuned solely on these seven geometries.

These are simulated 3D meshes, not measured object physics or PHINO/DINOv2 training results.
